# 공고문 생성 STEP 01~10 사용자 흐름 다이어그램 설계

## 목표

현재 상단의 `전체 사용자 플로우` 다이어그램을 제거하고, 문서 하단에 카드 목록으로 있는 `한눈에 보는 사용자 흐름`을 같은 자리로 이동한다. STEP 01~10의 기존 상태와 설명은 유지하되, 단계 사이를 화살표로 연결해 공고문 생성 순서를 한눈에 이해할 수 있게 한다.

## 화면 구조

- 상단 내비게이션의 다이어그램 링크 이름을 `한눈에 보는 사용자 흐름`으로 바꾼다.
- 기존 `#diagram` 위치에 같은 제목의 섹션을 둔다.
- 현재 원가계산서 검증·공고문 생성으로 분기되는 SVG와 숨겨진 이전 SVG는 제거한다.
- 하단 공고문 생성 설명 영역에 중복된 `한눈에 보는 사용자 흐름` 제목과 기존 10개 카드 목록은 제거한다.
- `단계별 상세내역`, 입력 범위, 마일스톤, 개선 체크리스트는 현재 위치와 내용을 유지한다.

## 다이어그램

다이어그램은 접근 가능한 HTML/CSS 카드로 만든다. 각 카드는 STEP 번호, 상태 태그, 단계명, 현재 설명을 포함한다.

데스크톱에서는 두 줄의 지그재그 흐름으로 배치한다.

```text
STEP 01 → STEP 02 → STEP 03 → STEP 04 → STEP 05
                                            ↓
STEP 10 ← STEP 09 ← STEP 08 ← STEP 07 ← STEP 06
```

단계와 상태는 기존 내용을 그대로 사용한다.

1. 공고문 생성 진입 — 동작
2. 원가계산서 입력 — 동작
3. 원가계산서 자동 채움 — 일부 동작
4. 유형별 정보 입력 — 일부 동작
5. 필수값 확인 — 일부 동작
6. 금액 확인 — 동작 안함
7. 날짜·공휴일 확인 — 동작 안함
8. 유형별 템플릿 선택 — 일부 동작
9. HWPX 생성·다운로드 — 일부 동작
10. 한글에서 최종 확인 — 동작 안함

상태색은 현재 문서의 녹색·주황색·빨간색 토큰을 재사용한다. 화살표는 중립 회색으로 표시하고 카드보다 시각적 우선순위를 낮춘다.

## 반응형·인쇄

- 데스크톱: 5개씩 두 줄로 배치하고 05→06은 아래로, 06→10은 오른쪽에서 왼쪽으로 연결한다.
- 모바일: STEP 01부터 STEP 10까지 한 열로 재배치하고 모든 화살표를 아래 방향으로 바꾼다.
- 문서 전체의 가로 스크롤은 발생하지 않아야 한다.
- 인쇄 화면에서도 단계 순서와 상태색이 유지되어야 한다.

## 검증 기준

- `#diagram` 섹션에 STEP 01~10이 각각 한 번만 존재한다.
- 데스크톱에서 01→05→06→10의 지그재그 순서가 보인다.
- 모바일에서 01~10이 세로 순서로 보인다.
- 상태별 카드 수는 동작 2개, 일부 동작 5개, 동작 안함 3개다.
- 기존 상세내역 10행과 개선 체크리스트 38개는 손실되지 않는다.
- TypeScript 검사와 브라우저 렌더링 확인을 통과한다.
